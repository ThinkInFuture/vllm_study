1. 整体架构总览

同一个 Kimi K3 模型，在三个硬件平台上需要不同的底层算子实现。vLLM 的设计是：

  • NVIDIA 和 AMD 是上游 vLLM 的内建实现，各自独立完整地实现了整个模型
  • Ascend 是外部硬件插件，通过继承上游类、替换 NPU 特定组件来适配

3. 平台路由机制

上游入口：vllm/models/kimi_k3/__init__.py

上游通过检测当前平台，自动路由到对应的实现：

# vllm/models/kimi_k3/__init__.py
from vllm.platforms import current_platform

if TYPE_CHECKING:
    from .nvidia.model import KimiK3ForConditionalGeneration
elif current_platform.is_rocm():
    from .amd.model import KimiK3ForConditionalGeneration  # AMD
elif current_platform.device_type == "tpu":
    pass  # TPU插件自己注册，不在此加载
else:
    from .nvidia.model import KimiK3ForConditionalGeneration  # NVIDIA

Ascend 入口：vllm_ascend/models/kimi_k3.py

Ascend 插件绕过上述路由，直接继承上游 AMD 版本的类，并替换关键组件：

关键代码对比：残差计算核心

# ─── AMD 版 (amd/linear.py:141) ─── 调用 ROCm Triton kernel
def _apply_attn_res(prefix_sum, block_residual, proj, norm, num_valid_blocks, ...):
    return attn_res(prefix_sum, delta, block_residual,
                    norm.weight, proj.weight.squeeze(0), ...)

# ─── Ascend 版 (kimi_k3.py:92) ─── 优先 NPU Triton，回退纯 PyTorch
def _apply_ascend_attn_res(prefix_sum, block_residual, proj, norm, num_valid_blocks):
    if apply_attn_res is not None and prefix_sum.device.type == "npu":
        return apply_attn_res(...)                    # ← NPU 加速路径
    # 纯 PyTorch 回退（数学等价）
    values = torch.cat((block_residual[:,:num_valid_blocks,:], prefix_sum.unsqueeze(1)), dim=1)
    values_fp32 = values.float()
    inverse_rms = torch.rsqrt(values_fp32.square().mean(-1, keepdim=True) + norm.variance_epsilon)
    normalized_without_gamma = values_fp32 * inverse_rms
    score_weight = norm.weight.float() * proj.weight.squeeze(0).float()
    scores = (normalized_without_gamma * score_weight).sum(-1)
    probabilities = scores.softmax(-1).unsqueeze(1)
    return torch.matmul(probabilities, values_fp32).squeeze(1).to(values.dtype)

6.3 forward_attn_residual 对比

AMD forward_attn_residual

def forward_attn_residual(self, positions, hidden_states, block_residual):
    prefix_sum = hidden_states
    hidden_states = _apply_attn_res(
        prefix_sum, block_residual,
        self.self_attention_res_proj,
        self.self_attention_res_norm,
        self.prev_valid_blocks,
        output_norm=self.input_layernorm,
        block_write_idx=(self.block_write_idx
            if self.is_block_write_layer else -1),
    )
    if self.is_block_write_layer:
        prefix_sum = None

    hidden_states = self._run_self_attn(positions, hidden_states)

    if prefix_sum is None:
        prefix_sum = hidden_states
        prefix_delta = None
    else:
        prefix_delta = hidden_states

    hidden_states = _apply_attn_res(
        ..., delta=prefix_delta,
        output_norm=self.post_attention_layernorm,
    )
    hidden_states = self.mlp(hidden_states)
    prefix_sum = prefix_sum + hidden_states
    return prefix_sum, block_residual

Ascend forward_attn_residual

def forward_attn_residual(self, positions, hidden_states, block_residual):
    prefix_sum = hidden_states
    hidden_states = _apply_ascend_attn_res(
        prefix_sum, block_residual,
        self.self_attention_res_proj,
        self.self_attention_res_norm,
        self.prev_valid_blocks,
    )
    if self.is_block_write_layer:
        block_residual[:, self.block_write_idx, :].copy_(prefix_sum)
        prefix_sum = None

    hidden_states = self.input_layernorm(hidden_states)
    if self.use_sequence_parallel:
        hidden_states = sp_all_gather(hidden_states)
        hidden_states = hidden_states[:positions.shape[0]]
    hidden_states = self.self_attn(...)
    if self.use_sequence_parallel:
        hidden_states = sp_reduce_scatter(hidden_states)

    prefix_sum = hidden_states if prefix_sum is None else prefix_sum + hidden_states
    hidden_states = _apply_ascend_attn_res(...)
    hidden_states = self.post_attention_layernorm(hidden_states)
    hidden_states = self.mlp(hidden_states)
    hidden_states = prefix_sum + hidden_states
    return hidden_states, block_residual

NVIDIA / AMD（内建平台）

  • 必须完整独立实现所有组件
  • 因为上游需要为每个平台提供开箱即用的支持
  • 两者逻辑相似但算子不能混用

  • 继承为主，替换为辅
  • 只替换硬件强相关部分（KDA算子、attn_res）
  • 新增 NPU 特有逻辑（序列并行、量化透传）
  • 879 行（其中大量是继承的上游逻辑）

最终结论

不是每个平台"都写一遍"同一份代码，而是：

  • NVIDIA 和 AMD 各自完整独立实现（因为它们的算子生态完全不同，且是上游内建）
  • Ascend 通过继承 AMD 版本，只替换 NPU 特有的底层算子和内存管理策略，上层的模型结构、权重加载、前向框架全部复用
  • 越靠近算子层，差异越大（必须替换）；越靠近模型层，共性越多（可以继承）
  • 如果未来 Ascend 被合并进上游，它也会变成 vllm/models/kimi_k3/ascend/ 下的一套完整实现，届时代码量会大幅增加

那"依赖 AMD"到底是什么意思？——三种机制，对应到代码

# 机制一：整类继承 —— 类体是空的或只加参数，方法全部来自 AMD 基类
class AscendKimiMLAAttention(UpstreamKimiMLAAttention):   # Upstream = vllm/models/kimi_k3/amd/linear.py
    def forward(self, positions, hidden_states):
        return self.mla_attn(positions, hidden_states)     # 只改一个委托点

# 机制二：继承 + 覆盖 —— 方法签名沿用 AMD 基类，实现重写
class AscendKimiDecoderLayer(UpstreamKimiDecoderLayer):
    def forward_attn_residual(self, ...): ...              # 同名同序，换掉残差函数/注意力分派

# 机制三：整组件替换 —— 上游类彻底不用，接口对齐
self.self_attn = AscendKimiK3DeltaAttention(...)           # AMD 的 KimiK3DeltaAttention 被丢弃

一句话：AMD 提供的是"层的组织方式"（方法顺序、组件接线、权重加载），昇腾提供的是"每个动作怎么算"。 时序图里的编号 ①→⑤ 就是 AMD 基类定下的顺序；每个编号算什么，红色算子说了算。

三个算子通道怎么区分（对应真实代码）

通道是什么Kimi K3 里在哪用为什么选它
torch.ops._C_ascend.* vllm-ascend 自己编译的 C++ 扩展 vllm_ascend_C（utils.enable_custom_op 惰性注册），内部算子用华为 AscendC 语言写，随包发布 KDA 全部核心计算：chunk_kda_fwd（prefill 分块）、recurrent_kda（decode 递归）、npu_causal_conv1d_custom（因果卷积） 上游没有的算子（KDA 是 Kimi K3 新结构），必须自己写设备代码
torch_npu.npu_* 华为官方 torch_npu 库提供的 aclnn 算子（CANN 自带，随固件/驱动发布） MLA 的融合推理注意力（FIA）、MoE 的 npu_grouped_matmul_swiglu_quant、各类基础算子 通用大算子华为已高度优化，直接调用即可，无需自研
@triton.jit（triton-ascend） Triton 语言的 Ascend 后端，Python 写 kernel、运行时编译到 NPU 注意力残差 _apply_attn_res_kernel（ops/triton/kimi_k3/attention_residual.py） 与 NVIDIA/AMD 共享同一份 Triton 源码风格，移植成本低；无环境时回退纯 PyTorch

把两个问题串起来（本章结论）

  • "看不到 Ascend 实现全景"：因为 70% 的实现是"继承来的"（引擎/runner/模型骨架），真正的 Ascend 代码集中在 worker/（执行器）、attention/（注意力后端）、ops/（算子）、models/（适配层）四处——第 9 章调用链把它们挂回了同一条链上。
  • "和 Ascend 底层串不起来"：中间缺的是"算子通道"这一环——vllm-ascend 从不直接摸硬件， 它只会走 torch.ops._C_ascend（自研 AscendC）、torch_npu（华为 aclnn）、 triton-ascend 三个入口，再由 CANN 完成编译与调度落到 AI Core（本章图 10）。
