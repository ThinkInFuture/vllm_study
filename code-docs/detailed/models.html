模型定义 (models/)

深入理解模型注册机制和各模型实现

一、模块概述

models目录是vLLM Ascend的模型注册中心，负责将NPU优化的模型注册到vLLM，使其可被加载和执行。

核心职责

  • 定义模型注册入口函数 register_model()
  • 将模型名称映射到具体的模型类
  • 支持多种模型架构（DeepSeek、Kimi、MiniMax、Qwen等）
  • 支持投机解码的草稿模型

一、模块上下游关系

models模块是vLLM Ascend插件的核心模块之一，它负责将NPU优化的模型注册到vLLM的模型注册表中。理解这个模块的关键在于明白它在什么时候被调用，以及它与其他模块如何协作。

1.1 调用时机

models模块的注册函数会在vLLM引擎启动时被自动调用。整个流程是这样的：首先vLLM启动并扫描已安装的插件，然后调用插件的register_model函数，最后将所有NPU优化的模型注册到全局的ModelRegistry中。这样当用户请求推理时，vLLM就能找到对应的NPU优化模型。

1.2 与其他模块的关系

models模块与多个模块存在依赖关系。它依赖ops模块提供的自定义算子（如RMSNorm、激活函数等），依赖attention模块提供的注意力后端（如MLA、SFA等），还依赖quantization模块提供的量化支持。同时，models模块为worker模块提供模型类，worker模块负责实际执行推理。

1.3 数据流向

数据在模型加载和执行过程中的流向是：首先从HuggingFace的模型配置中获取model_type，然后在ModelRegistry中查找对应的类路径，接着动态导入模块并获取模型类，之后实例化模型并加载预训练权重，最后将模型对象传递给Worker模块执行推理。

1.4 完整生命周期

模型的完整生命周期从开发者编写模型代码开始，经过注册、加载、执行等多个阶段。注册阶段将模型添加到ModelRegistry中；加载阶段根据用户指定的模型名称查找并实例化模型；执行阶段接收推理请求并进行前向传播；最后模型可以被多次复用执行推理。

3.2 register_model() 函数

vllm_ascend/models/__init__.py
from vllm import ModelRegistry

# 这是模型注册的入口函数
# vLLM启动时会自动调用此函数
def register_model():
    # 注册Kimi K3因果语言模型
    # 参数1: 模型名称（用于HuggingFace配置匹配）
    # 参数2: 模型类的完整路径（用于动态导入）
    ModelRegistry.register_model(
        "KimiLinearForCausalLM",  # 模型名称
        "vllm_ascend.models.kimi_k3:AscendKimiLinearForCausalLM",  # 类路径
    )

关键点

模型名称：必须与HuggingFace模型配置中的 model_type 或架构名称匹配。
类路径：格式为 模块路径:类名，vLLM会动态导入这个类。

五、模型分类

models模块中注册的模型按用途可以分为三大类：主模型（CausalLM）、条件生成模型（ConditionalGeneration）和投机解码模型（MTP/DSpark/Draft）。主模型用于标准的文本生成任务；条件生成模型用于多模态任务，如图文理解；投机解码模型用于加速推理，通过草稿模型预测多个token，然后由主模型验证。

六、模型加载流程

模型加载是models模块的核心功能之一。当用户指定一个模型名称时，vLLM会按照以下流程加载模型：首先在ModelRegistry中查找模型名称对应的类路径，然后使用Python的importlib动态导入模块，接着获取模型类并实例化，最后加载预训练权重完成模型初始化。

    @staticmethod
    def get_model_class(model_name):
        # 返回类路径字符串，如 "vllm_ascend.models.kimi_k3:AscendKimiLinearForCausalLM"

# 2. 动态导入（vllm/v1/worker/gpu_worker.py）
import importlib
module_path, class_name = model_cls_path.split(":")
module = importlib.import_module(module_path)
model_cls = getattr(module, class_name)

# 3. 实例化模型（vllm_ascend/models/kimi_k3.py）
class AscendKimiLinearForCausalLM(torch.nn.Module):
    def __init__(self, config):
        super().__init__()
        self.embed_tokens = nn.Embedding(config.vocab_size, config.hidden_size)
        self.layers = nn.ModuleList([...])
        self.norm = RMSNorm(config.hidden_size)

# 4. 加载权重（vllm_ascend/models/kimi_k3.py）
def load_weights(self, weights_path):
    state_dict = torch.load(weights_path)
    self.load_state_dict(state_dict)

加载步骤详解

  • 步骤1：用户指定模型名称（如 "KimiLinearForCausalLM"）
  • 步骤2：在ModelRegistry中查找对应的类路径
  • 步骤3：使用Python的importlib动态导入模块
  • 步骤4：从模块中获取模型类
  • 步骤5：实例化模型并加载预训练权重
  • 步骤6：模型可用于推理

七、模型类结构

每个模型类都继承自torch.nn.Module，包含初始化函数和前向传播函数。初始化函数负责定义模型的各个层（如嵌入层、注意力层、FFN层等），前向传播函数负责定义数据在这些层之间的流动方式。不同模型的结构可能有所不同，但基本框架是相似的。

注册新模型步骤

  1. 在models目录下创建模型实现文件
  2. 在__init__.py的register_model函数中添加注册调用
  3. 确保模型名称全局唯一
  4. 使用完整的类路径（模块路径:类名）
  5. 添加注释说明模型用途
  6. 测试模型加载和推理

常见问题及解决方案

  • 问题1：模型名称重复 - 解决：检查并修改模型名称
  • 问题2：类路径错误 - 解决：检查模块路径和类名是否正确
  • 问题3：模块导入失败 - 解决：检查依赖是否安装，路径是否正确
  • 问题4：模型类不存在 - 解决：检查模型类是否正确定义和导出
