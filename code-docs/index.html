    华为昇腾NPU优化的vLLM推理引擎插件

    一、项目简介

    vLLM Ascend（vllm-ascend）是 vLLM 社区维护的硬件插件，让 vLLM 可以无缝运行在华为昇腾 NPU 上。该项目的核心目标是将vLLM的高性能推理能力扩展到华为昇腾NPU硬件平台，使用户能够在昇腾NPU上获得与GPU相当的推理性能。

    通过这个插件，用户可以像在GPU上使用vLLM一样，在昇腾NPU上部署和运行大语言模型。插件会自动处理NPU特有的硬件特性，包括内存管理、算子优化、通信优化等，用户无需修改任何代码即可在昇腾NPU上运行模型。

    支持 Atlas 800I A2、Atlas A2 Training、Atlas 800I A3、Atlas A3 Training、Atlas 300I Duo 等硬件。这些硬件覆盖了从推理到训练的多种场景，可以满足不同规模的大语言模型部署需求。

    项目特点

    1. 无缝集成：作为vLLM插件，无需修改现有代码即可使用

    2. 高性能优化：针对昇腾NPU特性进行深度优化

    3. 多模型支持：支持DeepSeek、Kimi、MiniMax、Qwen等多种模型

    4. 分布式推理：支持张量并行、流水线并行等分布式策略

    二、项目文件结构

    vllm-ascend项目采用标准的Python项目结构，核心源码位于vllm_ascend目录下。每个子目录对应一个功能模块，职责清晰，便于维护和扩展。理解文件结构是深入学习项目的第一步。

    源码结构导航

    想逐文件浏览全部 457 个源码文件的职责讲解、每个函数的行数与定义，并一键跳转真实源码？请进入 全景源码导航（panorama.html） ，或在任意 panorama 页面点击文件名旁的「查看源码」直达对应 .py 文件。

    四、整体架构

    理解vllm-ascend的架构，首先要分清两个层面：一个是vLLM核心引擎（上游项目，负责通用的推理调度），一个是vllm-ascend插件（本项目，负责NPU硬件适配）。用户看到的Scheduler、Worker、vLLM Engine都属于vLLM核心引擎，不是本项目的代码；本项目只提供NPUPlatform、Attention Backend、Custom Ops等NPU适配层。

    4.1 vLLM核心引擎（上游，不是本项目）

    vLLM Engine：整个推理系统的入口，负责接收用户请求、管理推理会话、协调各组件工作。它不关心底层是GPU还是NPU，只负责上层调度。

    Scheduler调度器：负责请求的调度和资源分配。它决定哪些请求优先处理、如何分配显存/NPU内存、如何进行连续批处理等。Scheduler是vLLM的核心组件，与硬件无关。

    Worker执行器：每个Worker负责在一块GPU或NPU上执行实际的推理任务。Worker会调用底层的注意力后端、自定义算子等完成计算。vllm-ascend的工作就是让Worker能够在NPU上运行。

    4.2 vllm-ascend插件（本项目）

    NPUPlatform：封装昇腾NPU的硬件特性，告诉vLLM如何使用NPU。这是本项目的核心入口，通过Hardware Plugin接口注册到vLLM。

    Attention Backend：实现NPU上的注意力计算，包括标准注意力、MLA、SFA等后端。

    Custom Ops：实现NPU优化的自定义算子，如RMSNorm、SiluAndMul等。

    Model Runner：负责模型的前向传播，调用注意力后端和自定义算子完成计算。

    关键区分

    1. vLLM核心引擎（vLLM Engine、Scheduler、Worker）是上游项目提供的，负责通用的推理调度，与硬件无关

    2. vllm-ascend插件（NPUPlatform、Attention Backend、Custom Ops、Model Runner）是本项目提供的，负责NPU硬件适配

    3. 关系：vllm-ascend通过Hardware Plugin接口注册到vLLM，让vLLM能够在NPU上运行

    4.3 请求处理完整流程

    当用户发送推理请求时，请求经过以下流程：

    1. 用户请求：用户指定模型名称和输入文本

    2. vLLM Engine：接收请求，创建推理会话

    3. Scheduler：调度请求，分配资源，决定处理顺序

    4. Worker：在指定的NPU上执行推理任务

    5. NPUPlatform：提供NPU硬件抽象，管理NPU设备

    6. Attention Backend：执行注意力计算（标准/MLA/SFA）

    7. Custom Ops：执行自定义算子（RMSNorm、激活函数等）

    8. Model Runner：协调模型的前向传播

    9. 昇腾NPU：执行实际的计算

    10. 推理结果：将生成的文本返回给用户

    五、插件注册机制

    vllm-ascend通过vLLM的插件机制进行注册。当vLLM启动时，会扫描所有已安装的插件，并调用每个插件的register函数。vllm-ascend的register函数会返回NPUPlatform类，告诉vLLM这是一个NPU硬件平台。之后，vLLM会实例化这个平台类，完成NPU的初始化。

    插件注册流程：vLLM启动 → 扫描插件 → 调用register函数 → 返回NPUPlatform → 实例化平台 → NPU可用。这个流程确保了NPU平台能够在vLLM启动时正确初始化，为后续的推理任务做好准备。

    模型注册机制：除了插件注册，vllm-ascend还需要注册支持的模型。每个模型都有一个唯一的名称和对应的类路径。当用户指定模型名称时，vLLM会根据注册信息动态导入模型类并实例化。这种机制使得模型可以按需加载，避免了不必要的资源消耗。

    1. 插件注册：在platform.py中定义NPUPlatform类，通过register函数返回给vLLM

    2. 模型注册：在models/__init__.py中定义register_model函数，将模型名称映射到类路径

    3. 动态导入：使用Python的importlib动态导入模型类，实现按需加载

    六、核心模块详解

    vllm-ascend由多个功能模块组成，每个模块负责特定的功能。这些模块协同工作，共同实现了NPU上的高性能推理。下面详细介绍每个模块的功能和职责。

    core模块是项目的核心，包含KV缓存管理和调度器等关键功能。KV缓存管理负责管理模型推理过程中的键值对缓存，调度器负责请求的调度和资源分配。这些功能对于大语言模型的推理至关重要，直接影响推理性能和资源利用率。

    models模块定义了各种大语言模型的实现，包括DeepSeek V4、Kimi K3、MiniMax M3、Qwen3等。每个模型都有针对NPU优化的实现，充分利用NPU的硬件特性加速推理。

    attention模块提供多种NPU优化的注意力后端，包括标准注意力、MLA多头潜在注意力、SFA稀疏注意力等。不同的注意力后端适用于不同的模型架构，用户可以根据需要选择合适的后端。

    ops模块实现NPU优化的自定义算子，包括激活函数、线性层、MoE混合专家等。这些算子经过深度优化，能够充分发挥NPU的计算能力。

    worker模块是模型执行的核心，负责模型的加载、初始化和推理执行。它与vLLM的Worker模块对接，将NPU的优化能力暴露给上层应用。

    七、注意力后端

    注意力机制是大语言模型的核心组件，负责计算输入序列中每个位置与其他位置的相关性。vllm-ascend提供了多种注意力后端，针对不同的模型架构和硬件特性进行优化。选择合适的注意力后端可以显著提升推理性能。

    标准注意力后端（AscendAttentionBackend）：适用于标准的Transformer模型，实现标准的多头注意力计算。这是最通用的后端，适用于大多数模型。

    MLA注意力后端（AscendMLABackend）：专为DeepSeek系列模型设计，实现了多头潜在注意力机制。MLA通过将注意力计算分解为多个低秩投影，减少了计算复杂度和内存占用。

    SFA注意力后端（AscendSFABackend）：实现了稀疏注意力机制，适用于具有稀疏注意力模式的模型。SFA只计算部分位置之间的注意力，大大减少了计算量。

    选择逻辑：系统会根据模型的配置自动选择合适的注意力后端。如果模型使用MLA，则选择MLA后端；如果使用稀疏注意力，则选择SFA后端；否则使用标准注意力后端。

    1. 标准注意力：通用性强，适用于大多数模型，但计算复杂度高

    2. MLA注意力：针对DeepSeek优化，减少内存占用，提升推理速度

    3. SFA注意力：适用于稀疏模型，只计算部分注意力，大幅减少计算量

    八、推理流程

    当用户发送推理请求时，vllm-ascend会按照以下流程处理：首先接收用户的推理请求，然后由调度器进行调度和资源分配，接着Worker执行器开始执行推理任务，模型进行前向传播计算，最后采样器生成输出token。这个过程会循环进行，直到生成完整的输出序列。

    详细流程：1. 接收请求：系统接收用户的推理请求，包含输入文本和生成参数。2. 调度分配：调度器根据系统资源和请求优先级进行调度。3. Worker执行：Worker加载模型并开始执行推理。4. 模型前向：模型进行前向传播，计算每个位置的输出概率。5. 采样输出：根据采样策略生成下一个token。6. 循环生成：重复步骤4-5，直到生成结束符或达到最大长度。7. 返回结果：将生成的文本返回给用户。

    性能优化：在推理过程中，vllm-ascend会应用多种优化技术，包括PagedAttention（分页注意力）、连续批处理、量化加速等。这些优化技术可以显著提升推理吞吐量和降低延迟。

    推理流程详解

    1. 请求预处理：将输入文本转换为模型可处理的token序列

    2. 调度决策：根据系统负载和请求优先级决定处理顺序

    3. 模型执行：调用NPU进行模型的前向传播计算

    4. 采样生成：根据采样策略（如Top-K、Top-P）生成输出token

    5. 结果组装：将生成的token序列转换为文本并返回给用户

    九、技术栈

    vllm-ascend基于多种先进技术构建，这些技术共同支撑了NPU上的高性能推理。下面介绍每个技术组件的作用和特点。

    Python是项目的主要开发语言，提供了丰富的库和工具支持。Python的易用性和快速开发特性使得项目能够快速迭代和扩展。

    PyTorch是深度学习框架，提供张量计算和自动微分功能。PyTorch的动态计算图特性使得模型开发和调试更加方便。

    CANN是华为昇腾计算框架，提供NPU的底层计算支持。CANN包含了丰富的算子库和优化工具，能够充分发挥NPU的计算能力。

    vLLM是高性能推理引擎，提供PagedAttention、连续批处理等优化技术。vllm-ascend作为插件，将这些优化技术扩展到NPU平台。

    Triton是内核编译器，用于编写和优化GPU内核。triton-ascend是Triton的昇腾版本，支持在NPU上编写高性能内核。

    Ray是分布式框架，提供分布式计算和任务调度支持。Ray使得vllm-ascend能够轻松部署在多机多卡环境中。

    十、硬件支持

    vllm-ascend支持多种华为昇腾NPU硬件，覆盖从推理到训练的多种场景。不同的硬件具有不同的计算能力和内存容量，用户可以根据实际需求选择合适的硬件。

    Atlas 800I A2：面向推理场景的高性能NPU，具有大容量HBM内存和高计算密度，适合部署大规模语言模型。

    Atlas A2 Training：面向训练场景的NPU，支持高吞吐量的训练任务，适合模型微调和预训练。

    Atlas 800I A3：新一代推理NPU，相比A2有显著的性能提升，支持更先进的计算特性。

    Atlas A3 Training：新一代训练NPU，提供更强的计算能力和更大的内存容量。

    Atlas 300I Duo：双芯NPU，通过两个芯片协同工作，提供更高的计算性能。

            DeepseekV4Layer(config) for _ in range(config.num_hidden_layers)

    def forward(self, input_ids):
        hidden_states = self.embed_tokens(input_ids)
        for layer in self.layers:
            hidden_states = layer(hidden_states)
        return hidden_states
