PA workspace 跨层复用

通用 GQA/PA性能优化PR #15579已合入 main作者 solin28825 · 2026-09-04 · 改动 1 文件 +42/-10

一、需求背景

图模式下走 _npu_paged_attention（PA）路径时，每步 decode 前要更新图参数 （update_paged_attention_graph_param，attention/attention_v1.py）。优化前的循环里， 每一层都调用一次 torch_npu._npu_paged_attention_get_workspace：

  • 28 层模型 = 每步 28 次调用
  • 每次调用背后是一块 36-54MB 的缓冲分配 + 一次 host 侧 "Setup" 往返

同一 decode 步内，所有层的形状和 seq_lens 完全相同——28 次查询查的是同一个结果， 纯粹是重复劳动，还把 host 侧 ACL API 时间线撑爆。

二、相关流程

图1 · 改动前：每层一次 get_workspace（28 层 = 28 次分配 + Setup 往返）
sequenceDiagram participant H as Host participant D as NPU loop 每层 ×28 H->>D: get_workspace（36-54MB 分配 + Setup 往返） H->>D: graph_task_update_begin + PA 执行 end Note over H,D: Setup 时间 ≈ 2× Execute 时间（实测比 2.000）

改动后：workspace 查询提到循环外，每轮更新只查一次、跨层复用； 只有当尺寸相关输入变化（seq_lens 张量身份 (data_ptr, shape) 及各形状/dtype 组成 的 key 不匹配）才重新查询。这与 FIA 路径已有的 graph_params.workspaces[num_tokens] 复用形态对齐。

图2 · 改动后：每轮一次查询，跨层复用（key 不匹配自动回退重查）
sequenceDiagram participant H as Host participant D as NPU H->>D: get_workspace（本轮仅 1 次） loop 每层 ×28 H->>H: ws_key 匹配？→ 复用 workspace H->>D: graph_task_update_begin + PA 执行 end Note over H,D: Setup/Execute 比例 2.000 → 1.036

三、需求改动

单文件改动（attention/attention_v1.py，+42/-10）。三点设计值得注意：

设计点说明
ws_key 覆盖全部尺寸输入(data_ptr, shape) + query/key_cache/value_cache 的 shape 与 dtype + block_table.shape——异构层配置只是触发重查，绝不会复用错误尺寸
只做轮内复用，刻意不做跨步workspace 大小还依赖 seq_lens 的数值（实测 len≤80 时 36MB、len≤400 时 54MB，随 decode 增长）——上一步的缓存可能偏小，复用有风险
保守回退任一层 key 不匹配 → 立即走一次全新 get_workspace，正确性优先
