RoPE cos/sin 索引+拷贝融合为单次 gather

DeepSeek-V4性能优化PR #14428已合入 main作者 ivyilike · 2026-09-03 · 改动 1 文件 +20/-7

一、需求背景

DeepSeek-V4 的 DSA 稀疏注意力需要按 token 位置取 RoPE 的 cos/sin 表 （get_cos_and_sin_dsa，ops/rope_dsv4.py）。优化前的写法是经典的 「先索引、再拷贝」两步式：

  • curr_cos = full_rope_cos[pos_tensor] —— 高级索引，分配一个新张量（host 侧 malloc）
  • buf_cos[:num_tokens].copy_(curr_cos) —— 再拷进常驻缓冲（又一次 kernel 分发）

cos/sin 各来一遍 = 每对 4 个算子。decode 路径每步、每层都要做， host 侧的分发次数和临时对象分配都翻倍——而真正想要的只是「把表里若干行写进缓冲」这一个动作。

改动后：用 torch.gather(..., out=...) 把「选行 + 写入」合成一个算子、 直接写进常驻缓冲——每对 4 ops → 2 ops，省 2 次分发和 2 次中间分配（消除 host 侧分配/GC 压力）。 gather 索引的构造技巧：把 pos_tensor 变形为 (num_tokens,1,1,1) 再沿旋转维 expand， 让 dim=0 的 gather 恰好选中 pos_tensor[i] 那一行。

三、需求改动

单文件改动（ops/rope_dsv4.py，+20/-7）。缓存路径（use_cache）换成 gather 直写； 无缓存路径保留原索引写法（本就要分配新张量，无收益）；语义完全等价，无 API 变化。

效果（PR 实测）：get_cos_and_sin_dsa 单次调用 814μs → 701μs（约 -14%）。decode 路径每步都调用，稳定缩小每步的 host 开销。
