基于现象的分析

输入：① 现象（60 分 @08-29 / 90 分 @09-05 / 都是 0.27.1 / head e6a133f7 → c1bb35f7）。输出：劣化性质判定 + 修复窗口定位 + 与 GLM 案的关系。

分析结论（先行）： ① 不是 vLLM 版本问题（坏/好都是 0.27.1）—— 与 GLM 案相同的排除逻辑； ② 劣化发生在 e6a133f7（08-29），恢复发生在 c1bb35f7（09-05）之前 —— 回归与修复都落在 vllm-ascend 的 08-29 → 09-05 代码窗口内； ③ 劣化幅度 89.9 → 60（-30 分）而非归零 —— 部分题受损，与 GLM 案的严格全零是不同性质的机制，两案根因大概率不同。

分析一 · 排除 vLLM 版本（与 GLM 案同一逻辑、不同结果）

运行vLLM得分推论
08-29 #1120.27.160.0同一 vLLM 版本下一坏一好 → 坏点不在 vLLM 上游，而在两次运行之间的 vllm-ascend 代码变更（e6a133f7 → c1bb35f7，约 7 天 500+ commits）之中：要么某个 commit 引入劣化后被另一个 commit 修复/回退，要么 08-29 为偶发劣化（见分析三）

与 GLM 案对照：GLM 案是"同版本下从好变坏且未恢复"（指向窗口内单向引入）；DSV32 案是"同版本下坏→好"（指向窗口内引入后又被修复/回退，或偶发）。两案机制不同。

分析二 · 劣化幅度形态：-30 分的部分受损，不是全灭

得分形态典型机制本案
严格 0.00（GLM 案）每个 token 都经过的路径被污染（量化/注意力数值错）→ 输出整体不可用GLM 案属于此类
89.9 → 60（部分受损）影响部分题目的机制：如 MTP 接受率下降导致思考链断裂、PD 分离传输的 KV 部分损坏、长序列场景特定分支出错、或采样参数下的质量下降DSV32 案属于此类：MTP2 + PD 分离 + 4 机，劣化集中在"部分题答错"，模型整体仍能作答

含义：DSV32 的坏点更可能在 MTP 投机解码质量 / PD 分离 KV 传输 / 长上下文特定分支，而不是 GLM 案那种全局数值污染。两案不值得强行合并归因。

分析三 · 偶发劣化假说（必须正视的备选）

反方观点：AIME2025 只有 30 题、采样 temperature 较高，60 分也可能是"某次运行状态差"（如硬件降频、网络抖动导致的 PD 传输重试、-prefix 缓存污染）的偶发表现 —— 毕竟 09-05 就恢复了。

正方观点：60 分 = 30 题里只对 18 题，比基线少对 11 题 —— 对一个 89.9 分水平的模型来说，这种幅度靠"运气差"解释偏弱；且 60.0 是三的倍数、与"部分题系统性答错"（如特定题型/特定 PD 路径的请求全部出错）吻合。

判决方法：找到 08-22 之前最近一次出分的记录（baseline 89.9 的测量时点），确认"好"的历史稳定性；或在当前 main 上重跑该 case 2 次 —— 稳定 90 → 当时的偶发/已修复；波动在 60~90 → 存在活着的间歇性问题。
