基于现象的分析

本页只做一件事：把 ① 现象 里的四组事实放在一起推演，得出从现象直接可证的结论。具体是哪个 commit / 哪个上游变更干的，见 ③ 可疑点 ④ 知识：SFA-C8。

分析结论（先行）：坏点被夹逼在 SFA-C8 路径（enable_sparse_sfa_c8=true 的稀疏注意力 + KV int8 索引）上； 该路径在 vLLM 0.26.0 下是好的（08-27 得 100 分），在 0.27.1 下全灭（0.00 ×3）—— 即 "0.27.1 窗口的变更 × SFA-C8 路径"的组合问题，不是任何单一因素的普遍故障。

分析一 · 同日对照逐项排除（最硬的一组推理）

分析输入（现象页 2.1）：09-04 同一天、同 vLLM 0.27.1、同一份模型权重（Eco-Tech/GLM-5.1-w8a8c8）、同 glm45/glm47 parser、同 MTP 配置（deepseek_mtp ×3 eager）、同 seed 1024 —— dual-nodes（sfa_c8 关）得 93.33，★198k（sfa_c8 开）得 0.00。

#两者相同的部分一好一坏 → 推出的结论
1同一份模型权重与加载流程模型本体、权重加载、tokenizer、前向计算没有坏
2同一个 vLLM 0.27.10.27.1 的通用路径（调度/采样/chat 模板）没有全局坏——"升级把一切都搞坏"不成立；这也回答了"为什么 qwen/deepseek 精度 job 全绿"
3同一个 --reasoning-parser glm45 + aisbench 提取93.33 正好 = baseline，思考与答案的输出结构与提取完全匹配——"reasoning 结构变了导致提取失败"不成立
4同一个 MTP 配置（deepseek_mtp ×3，eager）MTP 组合与坏无关（两边都开，一好一坏）
5唯一实质差异：sfa_c8 开关。另一处差异 max-model-len（133120 → 202752）对 AIME 短题（远小于两上限）无解释力坏点被夹逼在 SFA-C8 = 稀疏注意力 + KV int8 索引路径

分析二 · 得分时间线对齐（坏点"曾经是好的"）

分析输入（现象页 2.1 时间线行）：

日期镜像 vLLMsfa_c8=true 的精度推论
08-19 ~ 08-260.25.x → 0.26.0全部没跑到出分（部署/aisbench 故障）历史数据空缺，无法追溯更早
08-270.26.0100.00（30/30 全对）该路径在 0.26.0 下完全正常
08-30 / 09-04 / 09-060.27.10.00 ×3（严格一致）切换版本后立即且持续全灭
09-030.27.1当日配置仅 perf0.27.1 下该路径的吞吐仍能出数 → 坏的是"对错"不是"能不能跑"
推论：SFA-C8 路径并非从来就坏 —— 0.26.0 下好、0.27.1 下坏，坏点与版本窗口严格绑定。 同时说明 100 分不是运气（30/30 全对），0 分也不是波动（三次严格一致）—— 两个方向都是确定性机制。

分析三 · 家族矩阵归纳（开关分化，两种症状分层）

分析输入（现象页 2.1 / 2.2）：

观测事实推论
sfa_c8=true 的 2 个组网（★198k、128k-1k-90-50-PD）精度 0.00；后者 perf 同时从基线 1265 劣化到 469同开关同病 → 交叉印证，非孤例
sfa_c8=false 的组网（dual-nodes、128k_90_50）精度 93.33 / 吞吐正常（0.27.1 下）开关关闭即免疫 → 坏点在开关引入的路径里
weekly W8A8C8 系列（sfa_c8=false）时红时绿红 = TPOT 吞吐阈值不达标，与精度无关吞吐波动是另一层问题，与本案精度归因解耦（此前曾误把它们混为 SFA-C8 证据，已修正）
其他模型精度 job（qwen aime2024 / gpqa / R1 等）0.27.1 下全绿与"0.27.1 通用路径没坏"（分析一 #2）互相印证

分析四 · 评估链排除（"会不会是判分冤枉了它"）

质疑现象证据结论
会不会模型输出正常、aisbench 判 0？dual-nodes 用同一 aisbench、同一 glm45 parser、同一数据集得 93.33提取/判分链路对该模型正常 → "冤判"不成立（剩余可能仅限 aime2025 与 aime2024 链路差异，极弱）

会不会数据集缓存坏了？08-27 同缓存得过 100 分只剩"08-27 后缓存变坏"一种窄可能（弱）
